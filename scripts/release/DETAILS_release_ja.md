# Japan1925-GTFS—ファイルの詳しい説明

この文書は `DETAILS.md` の日本語訳です。内容が異なる場合は、英語版を優先します。

この文書は、データセットの `README.ja.md` を補足するものです。データセットの構成、すべてのファイル（「ファイルの一覧」）、書き起こしの層と統合の層、GTFSの層の詳細（番号つきの注意）、gtfs-validatorによる検査の結果、出どころの表、`extras/` のすべての表の列、経路検索用のネットワークを説明します。`README.ja.md` と `KNOWN_ISSUES.ja.md` は、下の「GTFSの層（`gtfs/`）の詳細」の項目を、見出しの番号と名前（たとえば「5. 運転間隔」）で指します。

## データセットの構成

このデータセットのデータは3つの層からなります。原本の表の書き起こし（`transcription/`）、原本の何か所かに掲載された同じ列車を1本の便にまとめた、便ごとの停車の時刻（`integrated/`）、GTFSデータ（`gtfs/`）です。`extras/` の派生表は、GTFSデータを原本へつなぎ、GTFSのファイルでは表せない原本の情報を残します。

書き起こしは、原本の時刻表を、帯と列車の方向（上り・下りなど）ごとに1枚ずつのシートに分けています。帯は、1つの時刻表を上下に分けた何段かのかたまりのことで、1つの帯には、1つの路線か、路線の一続きの区間を走る列車の時刻が載っています。たとえば64ページの「高岡・氷見間」の下リの時刻表は、「中越線」の高岡・越中中川・能町の帯と、「氷見線」の伏木・雨晴・島尾・氷見の帯に分かれています。

```
transcription/   原本の表：表の帯と方向ごとに 1 枚のシート
                 （時刻は 1 つのセル：シート・列・行）
      |   同じ列車を掲載したシートを 1 本の便につなぐ
      |   複数の路線をまとめた路線名の便は、境目の駅で分ける
      v
integrated/      便と停車地ごとに 1 行（trip_id、stop_id、source_sheet）
      |   計算した時刻と、雛形の便の時刻を加える（下の「5. 運転間隔」「6. 計算した時刻」）
      |   停車地の時刻が 1 つだけ記載されていれば、もう一方はそれを写す
      v
gtfs/            GTFS データ（trip_id、stop_id、stop_sequence）

extras/ が GTFS データを原本へつなぐ：
  stop_time_source.csv    trip_id + stop_sequence -> 各時刻のページ・シート・列・行
  stop_coord_source.csv   stop_id                 -> 各座標をどのように得たか
  trip_source.csv         trip_id                 -> 便のシートと、列車番号をどう決めたか
  physical_trains.csv     trip_id                 -> physical_train_id（1 本の通し列車の便）
```

## 書き起こしの層（`transcription/`）の詳細

### ワークブックのシート

`transcription/workbooks/` のファイルの各シートは、原本の表の帯1つを1つの方向について書き起こしたものです（帯をいくつかに分けたときは、その1つ）。シート名は表の識別子 `p<page>_tb<table>-<band>[-<segment>]` で、このデータセットのほかのファイルの `source_sheet` や `source_sheets` と同じです。各シートの行は次のとおりです。

| 行 | A列の見出し | 中身 |
|---|---|---|
| 1〜6 | `table_id`, `page`, `table_name`, `line_name`, `direction_raw`, `direction` | 表の識別子、ページ、表の題と路線名、原本の方向（たとえば「上リ列車」）と、それを `outbound` か `inbound` にしたもの。 |
| 7 | `trip_id` | 原本の表の中で、その列車が左から何列目か。1つの列車は表計算の4列（`dep_time`、`dep_pm`、`arr_time`、`arr_pm`）を使います。 |
| 8 | `trip_label_header` | 列の頭に記載されているもの（列車番号、列車の種別、記号）を、原本どおりに書き起こしたもの。 |
| 9 | `trip_num` | その列の列車番号（「時刻・列車番号・座標の出どころ」を参照）。 |
| 10 | `trip_num_source` | 列車番号の決め方（「時刻・列車番号・座標の出どころ」を参照）。 |
| 11 | `trip_num_note` | 別の表から番号を取ったとき、その表と、列車を突き合わせた決まり（たとえば `from p0094_tb001-2 (match=dep@天王寺 6.43, 城東線)`）。 |
| 12 | `確認メモ` | 原本に記載された時刻以外の文と、表についての短い説明（日本語）。段落は見出しで始まります。【原本注記】は表の中に縦書きで記された注記で、「原本の文」＝駅名、著または發、時刻（午前、午後または時間帯不明）の形です。【表全体】は表全体について、【運航頻度】は船がどれくらいの頻度で運航するか、【海里】と【浬程】は距離、【運賃】は運賃、【凡例】は凡例、などです。「此間」で始まる文は、「此間12分毎ニ運轉」のような運転間隔の欄に記載された文です（下の「5. 運転間隔」を参照）。 |
| 13 | `stop_order` ほか | 列の見出し。 |
| 14〜 | | 各行は1つの駅を表します。`stop_order`、`stop_name`、`stop_type`（`station`、`port`、または支線との分岐の駅ならたとえば `branch:鹽竈線`）のあとに、各列車の4つのセルが続きます。 |

### 時刻の書き方

時刻は原本どおり、時と分を点で区切って書いています。`8.31` は8時31分、`4.40` は4時40分、`7.00` は7時0分です。ワークブックでは、時刻を数として入れたセルと文字として入れたセルが混ざっています。数のセルでは値の末尾の0が落ち、4時40分は `4.4`、7時0分は `7` になります（表計算ソフトでは、表示形式によって `4.40` と見えます）。`transcription_long.csv` では、どちらのセルの時刻も分を2桁で書いています。`dep_pm` と `arr_pm` は、午後なら `1`、午前なら `0` です（原本は午後の時刻を太字で示しています）。`/二日目` や `/土曜日` のような後ろの文字は、何日もかかる船の運航で、その時刻が何日目か・何曜日かを示します。時刻の横の乗り換えの印（＊）と、列車の最後の駅を示す下線は書き起こしておらず、時刻だけを書いています。これらの印は、`extras/physical_trains.csv` を作成する際にページの画像から読み取りました。

### `transcription_long.csv`

`transcription_long.csv` は、ワークブックの書き起こしを1つにまとめた縦長の表です。各行は、値が記載されている、シートと列車の列と駅の組1つを表します。列は `file`、`sheet`、`page`、`table_name`、`line_name`、`direction_raw`、`direction`、`column`（7行目）、`trip_label_header`（8行目）、`trip_label`（番号を付ける前のワークブックの9行目）、`trip_num`、`trip_num_source`、`trip_num_note`、`note`（9〜12行目）、`stop_order`、`stop_name`、`stop_type`、`dep_time`、`dep_pm`、`arr_time`、`arr_pm` です。どの駅にも値の無い列車の列（たとえば縦書きの注記だけの列）は、駅の欄を空にした1行で出します。31ページの「東京・橫濱港間」の表は、時刻の欄に「當分運轉休止」（当分のあいだ運転を休止）と記載されていて、列車がありません。この表の2枚のシート（`p0031_tb002-1` と `p0031_tb002-2`）には列車の列が無いので、行がありません。

## 統合の層（`integrated/`）の詳細

### `integrated_stop_times.csv`

`integrated_stop_times.csv` の列は、`trip_id` と `stop_id`（GTFSデータで使う識別子）、`gtfs_trip_key`（便のキー）、`line_name`、`direction`、`trip_num`、`stop_sequence`、`stop_name`、`stop_type`、`dep_time` と `arr_time`（`HH:MM`。夜中のあとも24:00を超えて数え、ほかの時刻系で記載された時刻はGTFSデータと同じく日本の時刻に直したもの）、`source_sheet` です。日付の記載された航路の表（189〜192ページ）の運航のうち54は、記載された時刻が同じ、同じ表の別の便にGTFSデータでまとめているので、`trip_id` が空です（`extras/printed_sailings.csv` の `merged_same_times_in_table`）。別の表の運航とまとめた28の運航は、この層に行がありません。

### GTFSデータとの違い

GTFSデータがこの層と違うのは、次の4点です。

1. 計算した時刻を足しています（`extras/estimated_stop_times.csv`）。
2. 時刻のある停車地が1つしかない便を、`extras/single_stop_trips.csv` に移しています。
3. `gtfs/frequencies.txt` の雛形の便を足しています。
4. 時刻のある停車地には、到着時刻と発車時刻の両方を入れています。片方しか記載されていなければ同じ値を入れ、通し列車が別の表に続くときはそこに記載された時刻を使います。時刻ごとの出どころは `extras/stop_time_source.csv` にあります。

## GTFSの層（`gtfs/`）の詳細

この節では、`gtfs/` のGTFSデータを使うときの注意を、番号つきで説明します。

### 1. 運行日

`calendar.txt` では、1925年4月の時刻表が1925-03-28から1925-04-30までの毎日運行するものとして扱っています。これはデータ上の取り決めです。原本では多くの便に運行日が指定されていないため、この取り決めによって、1925年4月のどの日付でも経路検索ができます。期間を4月より4日前から始めているのは、4月1日の行程で、それより前に出た列車や船を使えるようにするためです（最も長い便は大阪から那覇への船で、90.5時間かかり、104:30に着きます）。長い行程（東京から京城（ソウル）、哈爾賓（ハルビン）など）は2〜5日かかるので、経路検索ソフトは1日より長い行程を許す必要があります（OpenTripPlannerでは `maxJourneyDuration`）。

原本に運行日が明記されている運行も、毎日の運行としてGTFSデータに入れており、それらは原本に記載された内容とともに `extras/operating_days.csv` に一覧にしています。
- 日付の記載された航路の表（189〜192ページ）には、145回の運航が日付つきで記載されています（`extras/printed_sailings.csv`）。時刻は表ごとに1回だけ記載されているので、時刻が同じであれば、別の船や別の会社の運航も1本の便を共有します。95回の運航を14本の便で表しています。残りの50回は、記載された時刻が2つ未満です。44回は記載された時刻が無く（午前/午後、または「隨時都合」とだけある）、`extras/printed_sailings.csv` にだけ載せています。残りの6回は、1つだけ記載された時刻を、停車地が1つの便として `extras/single_stop_trips.csv` に保持しています。
- 16の船の便は、月の決まった日、1日おき、または休みの日を除く毎日に運航します。
- 147本の列車には「不」（不定期）の印があり、運行日は記載されていません。

`tools/make_printed_days_gtfs.py` は、これらの運行が原本に記載された日にだけ走るようにしたGTFSデータの写しを書き出します（`calendar_dates.txt`。日付のある運航は、それぞれ別の便になります）。歴史上の旅を確かめるときなど、日付が大事なときに使ってください。不定期の列車は既定では毎日のまま残します（変えるには `--irregular representative` か `drop`）。4月30日より後の運航は、`--include-after-period` を付けない限り外します。運行日が記載されていても、その日に実際に運行したとは限りません。

1つを除くすべての船の便について、`extras/service_frequency.csv` に、原本に記載された運航の頻度を記録しています。何も記載されていない便（`記載なし`）も含み、それらは毎日運航するものとみなしています。除いた1つは、頻度だけを記した運行である「琵琶湖周遊」の推定の便で、その原文は `extras/frequency_sections.csv` にあります。

### 2. 24:00より後の時刻

真夜中を過ぎて走る便は、時刻をそのまま数え続けます（`26:30:00`）。そのため、それより前の日に出発した便が、検索する日にもまだ走っていることがあります（何日もかかる便は104:30に達します）。暦の期間を1925-03-28から始めているのはこのためです。`examples/route_1925.py` は、各便をそれより前の日にも走るものとして扱い、`calendar.txt` は読みません。

### 3. 停車地・親駅と乗り換え

`stops.txt` では、*（駅名, 路線）* の組ごとに1つの停車地（stop）を管理しているので、物理的には同じ1つの駅でも、路線ごとに別の停車地として出てきます。同じ1つの駅と見なせる停車地は1つのまとまりにし、そのまとまりを「親駅」（parent station）と呼びます。`stops.txt` では、親駅も1行（`location_type=1`）として入れ、各停車地の `parent_station` にその親駅の `stop_id` を入れています。乗り換えの時間は `transfers.txt` に記録しています。同じ親駅の停車地どうしは0分、近くの親駅どうしは歩いて1〜13分（最も近い停車地どうしが1km以内。分速80mで、分単位に切り上げ）、離れて立つ同じ名前の駅どうしは最大39分です（下を参照）。歩く時間は親駅の組ごとに1回、それぞれの最も近い2つの停車地の間で測り（同じ路線で隣り合う停車地の組と、原本の哩程で前後の駅のあいだに置いた停車地〔`interpolated_mileage`〕は除きます）、その親駅のすべての停車地に適用します。

同じ名前で5km以内にある停車地は、1つの親駅にまとめます（原本は、町の駅を1つの名前で記載することが多いためです。名前は地域タグ（`〈朝鮮〉` など）を除き、旧字体と新字体を同じものとみなして比べます。同じ名前の停車地がそうしたまとまりを2つ以上作る際は、最も近いまとまりに入れます）。次の2つの場合は同名の別駅として扱い、別々の親駅にして、徒歩でつなぎます（このバージョンでは最大3.1km・39分）。

- 両方の位置が駅そのものを指す出典から来ていて、300mより離れている場合。
- 一方または両方の位置が代表点（港の近くの村や海岸の点など、最大で約1kmずれうるもの）で、300mにそうした点1つにつき1kmを足した距離より離れている場合。


同じ名前でも別々の親駅になるのは、たとえば敦賀・高知・博多の鉄道の駅と港、中野の2つの鉄道（「中央本線」と「西武鐵道新宿線」）の駅です。島の港の宮島〈嚴島〉と「山陽本線」の宮島駅は、海を隔てて約2km離れており、別々の親駅で、徒歩の乗り換えもありません。gtfs-validatorは、2kmより離れた停車地どうしの乗り換えを `transfer_distance_above_2_km`（参考の通知）として挙げます。名前が違っても50m未満しか離れていない停車地の一部も、1つの親駅にまとめています（たとえば「岩國」と「岩國驛」、「市驛」と「和歌山市」、「大阪」と「大阪（天保山）」）。50m未満でも、まとめると1本の便が同じ親駅を2回通る組など、まとめていない組もあり、たいてい歩いて1分の乗り換えでつないでいます。どの停車地をどの親駅にまとめたかは、`stops.txt` の `parent_station` で分かります。`transfers.txt` が無いと、路線と路線の間の乗り換えができません。経路検索ソフトの中には、このファイルから乗り換えを作らないものがあります。OpenTripPlannerについては、下の「12. OpenTripPlannerでの使用」を参照してください。

親駅へのまとめ方と徒歩の乗り換えは、`gtfs/stops.txt` の座標から、上の決まりで求めました。座標が代表点（`extras/stop_coord_source.csv` の `place`。`README.ja.md` の「駅の座標とその出典」を参照）の停車地では、徒歩の所要時間は概算値です。1925年には実際より離れていた停車地を歩いてつないだり、少し離れた停車地を1つの親駅にまとめたりしていることがあります。

### 4. 通し列車

原本の時刻表で、乗り換えなしに路線の境目を越える列車は、路線ごとに1本の便に分けています（原本は路線ごとに列車番号を付けているためです）。`extras/physical_trains.csv` は1本の実際の列車に属する便をまとめたもので、それらに続けて乗っても乗り換えと数えずに済みます。これはGTFSの `block_id`（同じ車両で続けて走る便をまとめる識別子）としては書いていません。`block_id` では、1本の列車の便が共通の区間で重なること（両方の路線の表がその区間を掲載しています）も、各便の時刻をその便が出発した日を基準に数えることも許されないためです。5つの `physical_train_id` には便が1本しかありません。そのうち4つは、相手の便が時刻のある停車地を1つしか持たず、代わりに `extras/single_stop_trips.csv` に入っています。5つ目（「東海道本線」の71、`PT_p0015_tb001_30_1`）は、相手の部分が、複数の路線をまとめた路線名（「東海道及山陽本線」）の下に掲載された帯で、その時刻がすべてほかの便に入っているため、独立した便になっていません。

### 5. 運転間隔

原本には、1本1本の時刻ではなく運転間隔で示した運行が2種類あります。時刻表の中で、列車の列の代わりに「此間12分毎ニ運轉」（この間12分ごとに運転）のように運転間隔を記した欄（以下、「運転間隔の欄」と呼びます）と、時刻表の外に始発と終発、運転間隔、所要時間だけを文章で記した運行（以下、「頻度だけを記した運行」と呼びます）です。GTFSでは、どちらも、こうした運行を表すために作った1本の便と、その便を繰り返す時間帯と運転間隔で表しています。この1本の便を「雛形の便」（template trip）と呼びます。雛形の便は `trips.txt`・`stop_times.txt` に、繰り返す時間帯と運転間隔は `frequencies.txt` に入っています。GTFSのソフトは、雛形の便の停車地の並びと停車地の間の所要時間を使い、`frequencies.txt` に記した時間帯の中で運転間隔ごとにこの便を繰り返して、1本1本の便を作ります。これらは**推定**の運行です。原本が示しているのは運転間隔で、個々の発車時刻ではありません。ある路線の、頻度だけを記した運行は、それだけで1つの路線（GTFSのroute）になります。そうした路線が時刻表の路線と同じ名前のときは、その `route_long_name` に、原本に記載された区間の名前を入れています（たとえば「駿豆鐵道線」の「沼津驛・三島町間」）。運転間隔の欄の雛形の便も、同じく独自の路線に置き、原本に掲載された便の路線には決して置きません。その路線は、原本に掲載された便の路線と同じ `route_short_name` を持ち、`route_long_name` の末尾が「頻度の推定便」です（たとえば「山手線」の「品川・池袋間・頻度の推定便」）。経路検索ソフトの中には、運転間隔で表された便と同じ路線で停車の並びも同じ便を、すべて運転間隔の便として扱うものがあります。別の路線に分けておかないと、そうしたソフトは原本に掲載された便を飛ばしてしまいます。運転間隔の欄と、頻度だけを記した運行の、それぞれの原文と、それをどう読んだかは、`extras/frequency_box.csv`、`extras/frequency_sections.csv`、`extras/frequency_only.csv` にあります（下の「派生表（`extras/`）の詳細」を参照）。

`frequencies.txt` の `exact_times` は、発車の時刻が決まっているもの（毎時何分と記載した欄＝`②毎時○分` と、発車時刻を並べた欄）では `1`、運転間隔だけを記載したものと、何分かを記さずに毎時発車とだけ書いたもの（`②毎時各分`）では `0` です（間隔ごとに1本というだけで、発車の時刻は決まっていません）。

### 6. 計算した時刻

`extras/estimated_stop_times.csv` には、計算によって求めた時刻をすべて一覧にしています。`departure_only_terminal`（始発駅の発車時刻と全体の所要時間だけを記載した表。到着＝発車＋記載された所要時間）と `frequency_section_template`（頻度だけを記した運行。途中の停車地は、下に書いた例外を除き、座標で測った隣どうしの直線距離で補間）です。それ以外の時刻は、記載されたものか、同じ停車地のもう一方の記載された時刻を写したものです。

`gtfs/stop_times.txt` では、GTFSの標準の欄 `timepoint` でおおよその時刻を示しています。停車地の時刻の少なくとも1つが原本に記載されていれば `1`、計算した時刻、運転間隔で表された運行の雛形の便、時刻が記載されていない停車地は `0` です。`timepoint` が表すのは時刻が正確かおおよそかで、記載されたかどうかではありません。それは `extras/stop_time_source.csv` が時刻ごとに示しています（`printed`、`copied`、`computed`、`template`。「時刻・列車番号・座標の出どころ」を参照）。そのため、`timepoint` が `0` の行は `estimated_stop_times.csv` の行より多くなります。運転間隔の欄の雛形の便（原本に掲載された列車の所要時間を写したもの）と、頻度だけを記した運行の各雛形の便の最初の停車地と時刻が記載されていない停車地は、`estimated_stop_times.csv` に挙げていないためです。`estimated_stop_times.csv` で `frequency_section_template` とした時刻は、`stop_time_source.csv` では `template` です。

原本がある停車地に到着か発車の一方しか記載していないときは、GTFSは両方を必要とするので、もう一方を同じ時刻にしています（`copied`）。そのため、到着と発車が同じ時刻でも、0分の停車とは限りません。

頻度だけを記した運行の雛形の便では、一部の途中の停車地に時刻がありません。同じ路線の、重なり合うほかの区間について原本が所要時間を記載している場合は、計算した時刻が記載された時刻と食い違わないよう、時刻を補間していないためです。GTFSでは、途中の停車地の時刻を空けてよいことになっています。経路検索ソフトの中には（たとえばOpenTripPlanner）、それを補間してそこで乗り降りさせるものがありますが、`examples/route_1925.py` はこれらの停車地を飛ばします。

### 7. 時差

原本には、日本と時差のある土地の時刻が混ざっています。原本が時差を記している場合（南満洲と中国沿岸の時刻は、日本と朝鮮の時刻より1時間、ハルビン時刻より26分遅い。したがってハルビン時刻は日本の時刻より34分遅い）は、その時刻を日本の時刻に直しています（+60分と +34分）。原本が時差を記していない時刻（台湾、ロシア極東、航路の海外の港）は原本どおりです。`agency_timezone` はAsia/Tokyoなので、ソフトはこれらの時刻を日本の時刻として読みます。1925年の台湾は、日本の時刻より1時間遅い西部標準時（UTC+8）を使っていました（明治28年勅令第167号。1896年1月1日から1937年9月30日まで施行）。ただし原本は台湾の表がどの時刻で書かれているかを記していないので、変換していません。台湾の時刻とみなす場合は、60分を足すと日本の時刻になります。

### 8. 駅名と路線名

#### 原本どおりの名前

駅名と路線名は、原本から書き起こしたとおりで、漢字と仮名だけです（ローマ字の名前はありません）。朝鮮の鉄道は、原本どおりの名前（「滿鐵京仁線」など）にしています。

#### 旧字体と新字体

駅名と路線名には、旧字体と新字体の両方が出てきます（たとえば `stops.txt` の駅名には、驛・鐵・靑と並んで青・横があります）。小さな活字では、旧字体と新字体のどちらが記載されているかをスキャンで見分けられないことがあります。公開した書き起こしの正確さを確かめるため、ワークブック178冊から無作為に選んだ20冊（うち3冊は人手で書き起こしたもの）で駅名60を抜き取り、原本と照らしました。そのうち2つは、原本が旧字体で記載しているのに新字体で書き起こしていました（靑森を青森と、橫手を横手と。どちらも126ページで、LLMエージェントが書き起こしたものです）。全ページを人手でもスキャン画像と照らし合わせていますが、ほかにも同じような例が残っているかもしれません。

駅名や路線名に、このデータセットで旧字体と新字体を同じ字として扱う字があり、その字が両方の字体で書かれている場合は、その名前のすべての駅や路線に1つの書き方を使います。まず路線ごとに多いほうの書き方にそろえ、次に路線をまたいで、そのとき多いほうの書き方にそろえます。そのため、駅がその駅自身のページには記載されていない字体で出てくることがあります（たとえば「宇和島鐵道線」の「大內」は、「國東鐵道線」の「大内」の字体に合わせて「大内」としています）。それ以外の書き方の違い（たとえば「瀬峯」と「瀬峰」、別の駅の「本郷」と「本鄕」）は、書き起こしたとおりに保持しています。

今の書き方（新字体）で駅を探すには、`extras/stop_name_variants.csv` を使ってください。名前を新字体に直したものと、書き起こしで使われている書き方を載せています。

#### 地域タグと路線の地域

同じ名前だが異なる地域にある駅は、駅名に `〈朝鮮〉` のような地域タグを付けて区別しています。`〈嚴島〉` は、「山陽本線」の宮島駅と海を隔てた島の港の宮島〈嚴島〉に付けた地域タグです（上の「3. 停車地・親駅と乗り換え」を参照）。

各路線の地域は `extras/route_region.csv` にあります（GTFSのファイルは標準の欄だけにしています）。北海道は「内地」と分けていますが、1925年当時の区分では、北海道は内地に含まれます。

#### 複数の路線をまとめた路線名

原本は、2つ以上の路線を走る列車を、「東海道及山陽本線」のような複数の路線をまとめた路線名の下に、1つの帯として掲載することがよくあります。帯を境目の駅で分けられる場合は、その便を、もとになる各路線に割り当てています。複数の路線をまとめた路線名のまま残る便もあります。帯を1つの駅で分けられない場合（たとえば「臺灣總督府鐵道縦貫線及臺中線」。ある路線から別の路線に入って戻ってくる帯です）と、通しの乗車（路線の境目で乗り換えずに乗り続けること）や、ほかのどこにも記載されていない時刻を、GTFSデータの中でその帯だけが残している場合です（`KNOWN_ISSUES.ja.md` の4節を参照）。それらの時刻と停車地は原本どおりです。

### 9. 識別子

識別子は、`stop_id` が `ST…`、親駅が `PS…`、`route_id` が `RT…`、`trip_id` が `TR…` の形です。

GTFSデータを作るときは、便を、路線名・方向（`outbound` か `inbound`）・列車番号を `__` でつないだ名前（たとえば `東海道本線__outbound__1`）で見分けました。この名前を「便のキー」と呼びます。列車番号が記載されていない便では、列車番号の部分は `U` で始まる仮の名前で、同じ番号の2本目の便には `_b` のような印が付きます。便のキーは、`extras/trip_source.csv` などの `gtfs_trip_key` や `trip_key` の列にあります。`trip_id` と違い、便のキーは、路線名や列車番号を直すと今後のバージョンで変わることがあります。

### 10. 列車番号

`trip_short_name` は、原本に記載された列車番号です。原本に番号が記載されていないときは空です（路面電車や船によくあります）。一部の便では、番号がその列の頭には記載されておらず、同じ列車を掲載した別の帯やシートから引き継いでいます（`extras/trip_source.csv` の `trip_num_source` が `inherited_same_line` か `inherited_diff_line`。「時刻・列車番号・座標の出どころ」を参照）。列車の種別（特急、急行）、等級、寝台車と食堂車の印は `extras/trip_attributes.csv` にあります。

### 11. 路線の形

#### 地図を描くための折れ線（`extras/route_lines.geojson`）

路線の形は、地図を描くための `extras/route_lines.geojson` に入れています。路線名ごとに1本、駅を走る順につないだ折れ線です。駅と駅の間は直線で、急行が駅を飛ばす区間は除いています。支線は `MultiLineString` の別の部分です。属性は `route_short_name`、`route_ids`（その名前の路線。空白で区切ります。頻度だけを記した運行の路線は含みません）、`structure`（`path`、`branched`、`cycle` または `disconnected`）、`n_stops`、`length_km`（区間の長さの合計）です。点はすべて `gtfs/stops.txt` の駅の座標です。線路の形ではなく、便の距離を測るためのものでもありません。

#### `shapes.txt` を入れていない理由

GTFSの `shapes.txt` は `gtfs/` に入れていません。この折れ線は路線ごとに1本で、支線や直通の運行を走る便の道筋をたどらないので、`shapes.txt` にすると、ソフトは便の長さを違う道筋で測ってしまいます。`shapes.txt` が無いとき、ソフトは続く停車地の間を直線で描きます。

### 12. OpenTripPlannerでの使用

#### 読み込みと必要な設定

OpenTripPlanner 2.10は、道路のデータなしでこのGTFSデータを読めます（2.10.0で確かめました）。必要な設定：`build-config.json` の `transitServiceStart` と `transitServiceEnd` が1925年を含むこと（既定では、すべての便が期間外として捨てられます）、`router-config.json` の `routingDefaults.maxJourneyDuration` が既定の24時間より長いこと（上の「1. 運行日」を参照。同梱の設定は96時間で、例の行程には足ります）。

#### 長く待つ行程（`searchWindow`）

出発前や乗り換えで長く待つ行程では、`routingDefaults.searchWindow` を広げてください（たとえば `"PT24H"` に）。OpenTripPlannerは、着く時刻が同じ行程のうち、最も遅く出るものを返し、その出発が検索の幅の外にあると、行程を何も返さないためです。たとえば、1925年4月1日 08:00の東京から哈爾賓〈滿洲〉への行程では、鉄道の東京駅から最も早く哈爾賓に着く列車が20:30に出るので、幅を12.5時間より広くしたときだけ見つかります。

#### 乗り換えの設定

OpenTripPlannerは `transfers.txt` から乗り換えを作りません。自分で徒歩の乗り換えを作り（道路網があればそれを使い、無ければ停車地どうしの直線距離から、`maxTransferDuration`〔既定30分〕以内で作ります）、`transfers.txt` は自分が作った乗り換えの時間にだけ使います。`transfers.txt` のすべての組が作られるよう、`build-config.json` の `maxTransferDuration` を45分以上にしてください（最も離れた組は3.1km離れています）。また、0分の乗り換えに2分が上乗せされないよう、`otp-config.json` に `"otpFeatures": {"MinimumTransferTimeIsDefinitive": true}` を設定し、`routingDefaults.transferSlack` を `"PT0S"` にしてください（原本には、到着と出発が同じ分の乗り継ぎが記載されています）。列車や船を何度も乗り継ぐ行程のために、`routingDefaults.maxNumberOfTransfers` を既定の12より大きくしてください（同梱の設定は30）。

#### `examples/route_1925.py` との違い

OpenTripPlannerは、`gtfs/stops.txt` の座標をもとに、`transfers.txt` で組になっていない駅どうしの徒歩も作るので、その行程は `examples/route_1925.py` の行程と違うことがあります。このファイルの乗り換えだけに限る設定はありません。自分で作る徒歩が無いと、親駅の中の乗り換えさえ失われます。また、`exact_times=0` の運転間隔をまる1間隔分の待ちとして扱い、路線の変わる通し列車を乗り換えと数え（上の「4. 通し列車」を参照）、道路のデータが無いと、停車地から停車地への検索を、別の駅への徒歩で始めたり終えたりできません。

### 13. 路線の種類

`route_type` は、路面電車や軽便鉄道（軌道）を含むすべての鉄道で `2`（鉄道）、船の運行で `4`（船）です。

## 時刻・列車番号・座標の出どころ

`gtfs/stop_times.txt` に入れた記載された停車の時刻は、どれも書き起こしのセルまでたどれます。計算した時刻と雛形の便の時刻は、もとにしたページと表までたどれます。同じ停車地のもう一方の時刻を写した時刻には、それ自身のセルはありません。駅の座標は、どれも出典までたどれます（計算した位置は、計算のもとにした原本の哩程と前後の駅まで）。書き起こしシートの名前は `p<page>_tb<table>-<band>[-<segment>]`（`table_id`）です。

### 停車の時刻

**`gtfs/stop_times.txt` の `timepoint`**（GTFSの標準の欄）：その停車地の時刻の少なくとも1つが原本に記載されていれば `1`。時刻がおおよそである場合、つまり記載された値から計算したもの（`extras/estimated_stop_times.csv` に一覧があります）、運転間隔で表された運行の雛形の便の一部（`gtfs/frequencies.txt`）、または空のときは `0`。

**`extras/stop_time_source.csv`**：`gtfs/stop_times.txt` の各時刻の出どころです。各行は `gtfs/stop_times.txt` の各行と対応し、同じ順に並んでいます（キー：`trip_id`、`stop_sequence`）。

| 列 | 意味 |
|---|---|
| `arrival_source`, `departure_source` | `printed`：原本に記載された時刻。`copied`：原本はこの停車地に時刻を1つだけ記載しており、GTFSは両方を必要とするので、もう一方を同じ値にしたもの（ページ・シート・列・行は空で、記載された時刻の側に記録しています）。そのため、到着・発車時刻が同じでも、停車時間が0分とは限りません。`computed`：記載された値から計算したもの（`basis` を参照）。`template`：運転間隔で表された運行の雛形の便（上の「5. 運転間隔」を参照）の時刻。空：時刻なし。 |
| `arrival_page`, `arrival_sheet`, `arrival_column`, `arrival_row`（と `departure_…`） | 記載された時刻の場所：1925年の冊子のページ（表が始まるページ。9〜10ページのように見開きの2ページにわたる表は、右のページに記載された時刻でも左のページを示します）、書き起こしシート、列（シートの7行目の `trip_id`）、行（A列の `stop_order`）。「此間12分毎ニ運轉」のような運転間隔の欄の `template` の行では、雛形が所要時間を写した列車の、記載された時刻の場所。`computed` の行では、所要時間を記載したページとシート。 |
| `arrival_time_system`, `arrival_jst_offset_min`（と `departure_…`） | 内地の外の運行について：原本が記載している時刻系（たとえば「南滿洲及支那沿岸時刻」）と、日本の時刻にするために足した分数（上の「時差」を参照）。記載された時刻は、GTFSの時刻からこの分数を引いたものです。`注記なし` は、その運行について原本が時刻系を明記していないことを示します（台湾、ロシア極東、海外の港）。その時刻は原本どおりで、分数は空です。 |
| `basis` | 計算した行と雛形の行、雛形の便の時刻が記載されていない停車地について：時刻のもとにしたもの（頻度だけを記した運行では、その識別子 `FQ…`）。 |

`printed` の時刻は、書き起こした値から作っています。午前・午後を24時間制に直し、夜中を過ぎた時刻は24:00を超えて数え（上の「2. 24:00より後の時刻」）、時差のある時刻は日本の時刻に直しています（上の「7. 時差」）。スキャンで数字をはっきり読み取れないところ（太字の3・8・9は似ています）は、前後の便や、同じ列車を載せたほかのページと合う読みを採っています。書き起こした値のうちごく一部は、原本の誤植と判断して直しています。直したのは、同じ列車の別の掲載箇所や前後の列車の所要時間から、正しい値を確実に判断できる場合だけです。直した値は書き起こしにも入れているので、原本に記載された値は `extras/misprint_corrections.csv` にだけあります（直した理由も載せています。上の「ファイルの一覧」を参照）。

### 列車番号

**`extras/trip_source.csv` の `trip_num_source` と `trip_num_sources`**：便の列車番号をどう決めたか。その便の記載された時刻のもとになった、書き起こしの列から取っています。`explicit_section`（帯の頭に記載）、`explicit_header`（表の頭に記載）、`inherited_same_line`（同じ路線・同じ方向の別のシートから引き継ぎ）、`inherited_diff_line`（同じ表の別の路線から引き継ぎ）、`uncertain`（記載されておらず、決められなかったもの。こうした便の `trip_short_name` は空です）。`trip_num_source` は、この順で最も優先度の高い値です。`trip_num_sources` は、すべての値を強い順に `|` で区切って並べます。雛形の便では両方とも空です。

### 駅の座標

**`extras/stop_coord_source.csv`**：`gtfs/stops.txt` の座標の出どころです。各行は `gtfs/stops.txt` の各行と対応します。`extras/single_stop_trips.csv`（時刻のある停車地が1つしかない便）にだけ出てくる停車地は `gtfs/stops.txt` に入っていないので、この表にも行がありません（このバージョンでは青島〈支那〉と出雲今市）。それらの座標は、`gtfs/stops.txt` にある同じ名前の停車地の座標と同じなので、出典はその停車地の行で分かります。

| 列 | 意味 |
|---|---|
| `coord_class` | `station`：出典の記録から取った、駅そのものの位置。`place`：駅そのものではなく、地名や施設（町内、村、港、神社）の代表点。点は、町・港・別の駅（たとえば近くの今の駅）についてのWikipediaの記事から取ることもあり、`reference_id` にリンクがあります。`estimated`：計算によって求めた位置。`unrecorded`（このバージョンでは使っていません）：位置の出どころが記録されていないもの。`reference` があれば、それは位置が一致する記録です。港では、船の発着場所そのもの（地図上の港や桟橋の点）を `station` としています。 |
| `coord_method` | `station_article`（Wikipediaの駅の記事）、`wikidata_station`、`n02_station`（国土交通省の鉄道データN02-25）、`historical_gazetteer_station`（歴史地名データにある、旧5万分の1地形図の駅）、`topographic_map_reading`（このプロジェクトが「今昔マップ on the web」の旧版地形図から読み取ったもの。`reference_label` に地図の地域・時期・図名・版を記録しています）、`station_point`（`station_article` と同じだが、記事の題名を `reference_label` に記していないもの）、`place_point`（出典の記録から取った代表点。地名や施設の点、または船が寄港する港や近くの停車地に使った駅の点）、`wikidata_item`（1925年の駅ではないWikidataの項目）、`adjacent_station`（このデータの別の停車地の位置に置いたもの。その停車地は `reference_label` と `reference_stop_id`。駅前の路面電車の停留場、同じ場所にある別の鉄道の駅、港に置いた停車地）、`interpolated_mileage`（1925年の原本に記載された哩程〔起点の駅からの距離。マイルで記載されている〕に比例して、前後の駅の間に置いたもの）、`interpolated_track`（同じことを、N02-25の今の線路に沿って行ったもの）、`interpolated_order`（原本が哩程を記載していない路線で、原本に挙がっている停車地の並びに沿って等間隔に置いたもの）、`computed_position`（前後の駅から計算したもの）、`unrecorded`（このバージョンでは使っていません）、`parent_station`（親駅は `reference_stop_id` の座標を使います）。 |
| `reference`, `reference_id`, `reference_label` | 出典、その識別子、項目の名前。識別子は、WikipediaやWikidataの版への恒久的なリンク、Wikidataの項目へのリンク、N02-25の駅のコード（`N02_005c`）、位置参照情報の大字・町丁目コード、歴史地名データのID、GeoNamesへのリンク、頻度だけを記した運行の原文に挙がっている停車地の並びを使ったときはその運行の識別子（`FQ…`）、地理院地図で読み取った点では地理院地図のアドレス（`https://maps.gsi.go.jp/`）です。親駅の行では空です（`reference_stop_id` を参照）。 |
| `reference_distance_m` | `gtfs/stops.txt` の座標と、参照した記録にある座標との距離（メートル）。記録に座標があるときだけです。 |
| `checked_within_km` | 座標を選ぶときに、駅の位置を示す別の記録と照らし合わせて採用した位置（ほとんどは代表点と推定の位置で、駅そのものの位置も一部あり、その多くはWikidataから）について、照らし合わせで許した最大の距離（km）です。 |
| `reference_stop_id` | `adjacent_station` と `parent_station` について：座標を使った停車地。 |
| `reference_note` | 一部の位置について、出典からどう値を読んだか：`read from the coordinate field of the cited source with an obvious typo corrected`（出典の座標の欄の明らかな誤記を直して読んだ）、`a coordinate given in the body of the cited source, not its main coordinate`（出典の本文にある座標で、記事の座標の欄のものではない）、`the cited revision shows this coordinate from Wikidata; it is not written in the revision text`（挙げた版の本文に座標が無く、記事はWikidataの座標を表示している。Wikidataの値は版のあとで変わることがある）。ほかは空。 |

このデータセットの代表点と補間した位置は、`README.ja.md` の「駅の座標とその出典」に挙げた出典と、1925年の時刻表に記載された哩程だけから求めました。

## 派生表（`extras/`）の詳細

この節では、`extras/` の表のうち次の10の表について、列を説明します。計算した時刻（`estimated_stop_times.csv`）、時刻のある停車地が1つしかない便（`single_stop_trips.csv`）、路線の地域（`route_region.csv`）、列車の種別と見出し（`trip_attributes.csv`）、運転間隔の欄（`frequency_box.csv`）、頻度だけを記した運行（`frequency_sections.csv` と `frequency_only.csv`）、船の運航の頻度（`service_frequency.csv`）、運行日（`operating_days.csv` と `printed_sailings.csv`）です。どれも、GTFSのファイルでは表せない原本の情報を残すための表です。原本から写した文言は書き起こしたとおりで、自由に書いた文（備考など）は日本語です。

`route_region.csv` と `frequency_only.csv` を除く表には、便を指す `trip_id` の列があります。`trip_id` は `gtfs/trips.txt` の便で、`extras/single_stop_trips.csv` に移した便では、その表の便です。

### 計算した時刻と、停車地が1つの便

#### `extras/estimated_stop_times.csv`

`gtfs/stop_times.txt` の時刻のうち、原本に記載されておらず、記載された値から計算して求めたおおよその時刻の一覧です（上の「6. 計算した時刻」を参照）。各行は、`gtfs/stop_times.txt` のうち、そうした時刻を持つ行と対応します。列は `trip_id`、`stop_id`、`stop_name`、`stop_sequence`、`arrival_time` と `departure_time`（`gtfs/stop_times.txt` と同じ）、`kind`（`departure_only_terminal` か `frequency_section_template`）、`basis`（時刻を何から計算したか）、`source_sheet`（その表の書き起こしシート）です。

#### `extras/single_stop_trips.csv`

時刻のある停車地が1つしかないために `gtfs/` に入れなかった便と、その記載された時刻です。各行は1つの便を表します。列は `trip_id`、`route_id`、`line_name`、`direction_id`、`printed_number`、`gtfs_trip_key`、停車地（`stop_id`、`stop_name`、`stop_lat`、`stop_lon`）、その `arrival_time` と `departure_time`、`source_sheet` です。ここだけで使う路線や停車地は `gtfs/` にありません。

### 路線と列車

#### `extras/route_region.csv`

各路線の1925年当時の地域です。各行は `gtfs/routes.txt` の1つの路線を表します。列は `route_id`、`route_short_name`、`route_long_name`（`gtfs/routes.txt` と同じ）と `region`（上の「ファイルの一覧」を参照）です。

#### `extras/trip_attributes.csv`

列の見出しに記載された、便の種別（特急、急行）、客室の等級、寝台車と食堂車の印などです。各行は原本に掲載された1つの便を表します（雛形の便は含みません）。

| 列 | 意味 |
|---|---|
| `trip_id`, `trip_key`, `line_name`, `direction`, `trip_num` | 便と、便のキー（上の「9. 識別子」を参照）とその各部分（路線名、方向、列車番号）。時刻が同じ運航を1本の便にまとめた場合（上の「1. 運行日」を参照）、いくつかの行が同じ `trip_id` を持ち、`trip_key` が違います。 |
| `kind` | 列の見出しがその列車を特急または急行と示しているときは `特急` または `急行`。それ以外は空。 |
| `classes` | 記載された客室の等級（たとえば1等・2等・3等なら `1.2.3`）。 |
| `sleeper`, `diner` | 見出しに寝台車（寝）や食堂車（食）の印があれば `1`。 |
| `label_header`, `label_section` | 列の頭と帯の始めに記載された見出し。書き起こしたとおりです（`\|` は、別々のシートの見出しを区切ります）。 |
| `other_tokens` | 見出しのうち、種別・等級・番号として読まなかった部分（たとえば不定期の列車の「不」、「直」、船の名前）。 |
| `source_sheets`, `note` | 書き起こしシート。日本語の備考。たとえば、見出しを、時刻には使わなかった同じ便の別の掲載から取った場合（表頭の表記は、時刻には使わなかった同じ便の別の掲載（シート）から）や、記載された見出しの番号が便と合わないので使わなかった場合（便の番号と合わないので使わなかった表頭の表記）。 |

### 運転間隔の欄と、頻度だけを記した運行

#### `extras/frequency_box.csv`

時刻表の2つの列の間に記載された「此間12分毎ニ運轉」のような運転間隔の欄の原文と、それを `gtfs/frequencies.txt` にどう読み込んだかです（上の「5. 運転間隔」を参照）。各行は1つの欄を表します。書き起こしでは、この欄が空の列になっています。

| 列 | 意味 |
|---|---|
| `box_id`, `page`, `sheet`, `columns` | 識別子（`FB…`）、ページ、書き起こしシート、運転間隔の欄を表す空の列（シートの7行目の `trip_id`）。 |

#### `extras/frequency_sections.csv`

頻度だけを記した運行を、`gtfs/frequencies.txt` にどう読み込んだかです（上の「5. 運転間隔」を参照）。各行は、1つの運行の1つの方向を表します。読んだとおりには変換できず、推定の雛形の便を与えた運行には、読んだとおりの行（`trip_id` は空で、理由を `note` に記録しています）と、方向ごとに足した行（`source` が `estimate` か `estimate_ship`）があります。記載された所要時間だけを推定の値に置き換えた場合は、その行自体の `source` が `estimate` です。

| 列 | 意味 |
|---|---|
| `section_id` | `extras/frequency_only.csv` の、頻度だけを記した運行（`id`）。 |
| `page`, `line_name`, `direction` | ページ、路線名、雛形の便の方向（`outbound` か `inbound`。変換しなかった運行では空のことがあります）。 |
| `origin`, `destination`, `stations` | 両端の駅と、一方から他方へ挙がっている駅。 |
| `first_dep`, `last_dep`, `duration_min`, `pm_reading` | `origin` からの始発と終発、所要時間（読んだとおり）と、午前・午後をどう読んだか（原本は午後の時刻を太字で示しています）。 |
| `interval_min_lo`, `interval_min_hi`, `headway_secs`, `exact_times`, `est_trips` | 記載された分単位の運転間隔、`gtfs/frequencies.txt` に書いた値、推定の発車回数。 |
| `trip_id` | `gtfs/trips.txt` の雛形の便。運行を変換しなかったときは空です（`note` を参照）。 |
| `source`, `note` | `csv`：原文から読んだもの。`estimate` と `estimate_ship`：所要時間や寄る順番が記載されておらず、推定したもの（根拠は `note` にあります）。`override`：人が直したもの。1つの運行は、所要時間が記載されているのに `estimate` です。阪堺線の惠美須町—宿院（`FQ055`）は「約6分」と記載していますが、約9kmで約6分ということはありえず、同じ表のほかの運行とも合わないので、30分を使用しています。記載された値は `extras/frequency_only.csv`（`duration_raw`）に残っています。 |

#### `extras/frequency_only.csv`

時刻表の格子が無く、文章（始発と終発、運転間隔、所要時間）だけで記載された運行（頻度だけを記した運行）の原文です。各行は1つの運行を表します（格子の外に記載されたほかの注記の行もあります）。ほとんどが路面電車と都市の路線です。この表は時刻表のシートとは別に書き起こしたもので、人がページごとに行った確認には含まれていません。

| 列 | 意味 |
|---|---|
| `id`, `page`, `position` | 識別子（`FQ…`）、ページ、ページの中の位置。 |
| `type` | 頻度だけを記した運行（時刻表の格子が無い）は `頻度だけを記した運行（時刻の格子なし）`。ほかの値は、時刻表とともに記載された文です：格子の外に記載された注記（`格子の外の注記…`）、始発と終発の時刻と運転間隔の欄だけを記載した表（`頻度記載…`。36ページのものは `extras/frequency_sections.csv` に読み込んでいます）、時刻が書き起こしにある格子（`格子あり…`）。 |
| `line_name_raw`, `section_raw`, `text_raw` | 原本どおりの路線名、運行の見出し、文章全体（改行は ／ で表します）。 |
| `stations` | 原本に挙がっている駅（・で区切ります。△ などの印は原本どおり）。 |
| `distance_fare_raw`, `first_last_raw`, `interval_raw`, `duration_raw` | 原本の哩程と運賃、始発と終発、運転間隔、所要時間。 |
| `already_sheet` | 同じ表の書き起こしシートがあれば、そのシート（無いときは `N` か `無し`）。いくつかの値には、括弧の中に短いメモを足しています。たとえば、その文言を書き起こしシートのメモの行に写したことなどです。 |
| `confidence`, `note` | 読みの確かさ（「高」か「中」。「中」のときは、読めなかった字を `note` に記録しています）、備考。 |

## 経路検索用のネットワーク

`tools/make_router_data.py` は、`gtfs/` と `extras/` だけから、経路検索用のネットワークを作ります。`router_data.json` と、同じデータをウェブページ用にした `router_data.js` です。同じGTFSデータからは、常にバイト単位で同一のファイルができます。このネットワークはGTFSデータに無いものを何も足さず、経路検索ソフトがそのまま探せる形にGTFSデータを書き直したものです。

### ネットワークの作り方

- 駅は `gtfs/stops.txt` の親駅です。行程の中では、駅の中で列車を乗り換えることができ、駅と駅の間は `gtfs/transfers.txt` の徒歩の乗り換えに沿ってだけ移れます（上の「3. 停車地・親駅と乗り換え」を参照）。
- 各便は、時刻つきの駅の並びになります。`gtfs/frequencies.txt` の各雛形の便は、`start_time` から `headway_secs` ごとに `end_time` まで繰り返し、繰り返した1本1本（推定の運行）には推定の印を付けます。推定の運行では、同じ駅の中で続く停車地を1つにまとめます。
- `extras/physical_trains.csv` で同じ `physical_train_id` に挙がっている便はその識別子を持ち、路線の境目を越えて同じ列車に乗り続けても乗り換えと数えません（上の「4. 通し列車」を参照）。

### `router_data.json` の中身

| キー | 中身 |
|---|---|
| `groups` | 駅：親駅ごとに `{stop_id: {"name", "lat", "lon"}}`。 |
| `name_to_groups` | すべての停車地名について `{name: [stop_id, …]}`。駅の名前と違う停車地名も含みます。1つの名前が、遠く離れた複数の駅に属することがあります。 |
| `trips` | 便と推定の運行1本ごとに1つのオブジェクト（JSONのまとまり）：`k` 便のキー（`extras/trip_source.csv` の `gtfs_trip_key`。推定の運行では `_freq` と番号を足します）、`t` `trip_id`（推定の運行では、その雛形の便）、`l` 路線名、`d` `outbound` か `inbound`、`n` 便のキーの列車番号の部分（`extras/trip_source.csv` の `original_trip_short_name` と同じ）、または推定の運行では記載された頻度（たとえば「此間12分毎」）、`s` 停車の順の駅、`dep` と `arr` 発車時刻と到着時刻（`HH:MM`。無いときは `null`。24:00以降の時刻は、便が出発した日の続きです）、`est` 推定の運行なら1、`sn` 駅の名前と違う停車地名（`s` の中の位置ごと）、`p` `physical_train_id`。 |
| `walks` | `{stop_id: [[stop_id, minutes], …]}`：駅どうしの徒歩の乗り換え。 |
| `router_params` | このネットワークで経路を探すプログラムが当てはめる、探し方の決まり（たとえば、着く時刻が同じ行程では乗り換えの少ないほうを採る）。 |
| `meta` | `source`（データセットの名前）、`feed_version`、駅と便の数。 |

発車時刻だけの便のために計算した到着時刻（`extras/estimated_stop_times.csv`）には、このファイルでは印を付けていません。見分けるには、`t` と、`gtfs/stop_times.txt` の `timepoint` 列を使ってください。
